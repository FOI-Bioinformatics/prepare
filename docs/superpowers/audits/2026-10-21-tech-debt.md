# Technical debt audit, 2026-10-21

Scope: the whole `prepare` package and its tests at commit 0862a9f (v0.11.0 plus the CI trim),
measured rather than read: radon complexity and maintainability, module and test file sizes,
the lint exemption lists in `setup.cfg`, mypy with `--disallow-untyped-defs`, a cross-file
duplication scan (normalised six-line windows), git churn since 2026-09-01, the full test suite
with coverage and per-test timings, and `pip list --outdated` in the development environment.
Nothing in the repository was changed. The two earlier audits
(`2026-10-12-code-audit.md`, `2026-10-21-sra-download-audit.md`) read code for defects; this
one asks what slows the next change down.

## 2. Findings

Severity here is cost to the next change, not correctness: H = every change in the area pays
for it; M = a class of change pays for it; L = tidiness.

### High

| D2 | `plugins/sourmash_plugin.py` against `cli/commands/containment.py` and `cli/commands/advanced_analysis.py` | The sourmash plugin repeats the argparse definitions and bodies of `parse_containment`, `plot_containment`, `diversity` and `taxonomy`: 28 duplicated windows with `containment.py`, 18 with `advanced_analysis.py`. ### The twelve deferred review minors (D5)

From the fix branch (0.10.2):

1. Plain (uncompressed) files are counted twice before compression in `_compress_files`.
2. `--no-verify-downloads` drops the XML spot count from a shared sidecar instead of leaving it.
3. A `NetworkError` raised without a keyword is classified `unknown` by `classify_download_error`.
4. `failed_accessions.txt` is unlinked by a clean run without a lock, racing a concurrent run.
5. Every process test in `tests/test_concurrency_processes.py` uses `--no-compress`.

From the sketch branch (0.11.0):

6. An interrupted sketch is counted as failed in the summary and exit code decision.
7. The interrupt warning is logged twice.
8. The store sketch lock wait (`STATS_LOCK_WAIT_SECONDS`) ignores the stop token.
9. A non-read exception in a sketch worker loses the records of accessions that finished.
10. `--signature` with a `.sig.gz` file prints a traceback instead of a message.
11. The store sketch cache compares file sizes and mtimes but not the k sizes of the cached signature.
12. A non-accession folder under `fastq/` makes `sra_sketch` fail instead of being skipped.

## 3. Remediation

### Quick wins (one plan, about one day)

`docs/superpowers/plans/2026-10-21-tech-debt-quick-wins.md`: the twelve minors (D5), the store
command preamble (D4), a removal version for the renamed commands (D8), a done marker on
executed plans (D7), and three guards so the counts above cannot grow (section 4).

### Before the next SRA feature (two to three days)

- Make the sourmash plugin a thin adapter (D2): each plugin command builds the matching
  `BaseCommand`, calls its `configure_parser` and `execute`; `finite_float` and
  `anchored_folder` move from `cli/base.py` to `core/validation.py` so the layer rule holds.
  Removes 46 duplicated windows, 4 broad handlers and the only layer violation.
- Split `data/sra/accession.py` and `data/sra/store_handoff.py` by responsibility (D1): prefetch
  and dump; verdict and compression; store hand-off. Add the new modules to `SPLIT_MODULES` in
  `tests/test_module_sizes.py` so they cannot regrow.
- Narrow the broad handlers in `data/file_io.py`, `data/taxonomy.py` and `data/registry_batch.py`
  and remove the three from the B902 list (D3). The atomic-write helpers come first.

### Over the next releases

- One module per release off the B902 and docstring lists (D3), tracked by the guard below.
- Annotate `data/sra/store_handoff.py` and `data/sra/retry.py`, then turn on
  `disallow_untyped_defs` for `prepare.data.sra` through a mypy override (D9).
- Split the three largest test files along the commands they cover (D6).

## 4. Guards against regrowth

The existing gates already block the worst outcomes. Three small tests close the gaps this
audit found; the quick-wins plan adds them:

1. A test that counts the B902 and D101-D103 exemptions in `setup.cfg` and fails when the count
   rises, like `KNOWN_EXCEPTIONS` already does for module size.
2. A test that no module outside `prepare/cli/` imports `prepare.cli`, which would have caught
   the plugin (D2). The plugin is listed as the one known exception until D2 is fixed.
3. A rank-C budget in `tests/test_module_sizes.py`: the number of functions at rank C may not
   exceed the current 105, so complexity is paid down rather than parked under the D gate.
